# Architecture Alignment Checklist

## Purpose
Use this checklist to align implementation work to `docs/development/CONSOLIDATED_ARCHITECTURE_SPEC.md`.

## How To Use
- Mark items complete only when code and tests both satisfy the requirement.
- If a requirement is intentionally deferred, add a dated note under the item.

## 1. Documentation Hygiene
- [x] Remove mixed-content corruption from architecture/security docs.
- [ ] Audit `docs/completed-features` for other transcript or mixed-topic contamination.
- [ ] Add a short "owner + last verified" block to architecture-critical docs.

## 2. Routing Conformance
- [ ] Enforce canonical mobile path shape: `mobile/{domain}` for Phase 1 domains.
- [ ] Ensure route names follow `{domain}.mobile.*` consistently.
- [ ] Add compatibility redirects from legacy mobile URLs where still in circulation.
- [ ] Add route tests for mobile entry points per Phase 1 domain.

## 3. Livewire-First Surface
- [ ] Inventory remaining Blade-only route-facing CRUD/workflow pages.
- [ ] Create migration plan by domain for each remaining Blade-heavy surface.
- [ ] Migrate highest-traffic user and admin flows to Livewire-first pages.
- [ ] Verify destructive actions include loading/disabled and confirmation behavior.

## 4. Authorization and Security
- [ ] Confirm policy checks cover mount/actions for sensitive Livewire flows.
- [ ] Remove or refactor role-name checks from handlers/components.
- [ ] Verify admin middleware remains boundary, not substitute for policy checks.
- [ ] Re-run security fuzzing and endpoint access matrix currently marked pending.
- [ ] Record final pass/fail results with timestamp and test command evidence.

## 5. Mobile and PWA
- [ ] Verify all Phase 1 mobile pages use shared mobile shell.
- [ ] Complete missing shared mobile primitives (list/detail/form helpers, states).
- [ ] Add persistent offline banner and queued action indicator behavior.
- [ ] Implement and test Timecards-only queued write replay for offline submit.
- [ ] Validate installability and standalone launch behavior on real devices.

## 6. Boot and Registry Hardening
- [ ] Add tests for deterministic domain provider discovery order.
- [ ] Add tests for duplicate-key warning and first-wins behavior in registries.
- [ ] Audit providers for forbidden cross-domain assumptions during boot.
- [ ] Move unavoidable cross-domain boot work to `app()->booted(...)`.

## 7. Performance
- [ ] Add/verify eager loading on list/detail screens with known N+1 risk.
- [ ] Ensure expensive shared query data is loaded once and passed downward.
- [ ] Add query-focused regression checks to high-risk dashboard and report flows.

## 8. Data and Migrations
- [ ] Verify ULID conventions for migrated models and relationships.
- [ ] Ensure migrated models have factories used in feature tests.
- [ ] Validate migrations follow current safe patterns used by this repo.

## 9. Quality Gates
- [ ] For each touched domain, ensure tests include authorized, forbidden, and CRUD path coverage.
- [ ] Ensure at least one non-admin permission-path test exists per sensitive area.
- [ ] Run targeted test commands and record outcomes.
- [ ] Run formatter for changed PHP files before merge.

## 10. Mobile Subdomain Readiness
- [ ] Ensure mobile links are generated by named routes, not hard-coded paths.
- [ ] Define mobile host strategy and route grouping constraints.
- [ ] Add host-aware tests for both path-based and subdomain-based mobile routing (during transition).
- [ ] Prepare redirect/canonicalization rules and SEO-safe rollout notes.

## Exit Criteria
- [ ] No unresolved architecture contradictions remain in active planning docs.
- [ ] Security verification state is explicit and current.
- [ ] Mobile route strategy is consistent across code, tests, and docs.
- [ ] Livewire-first migration plan is tracked for all remaining route-facing workflows.
